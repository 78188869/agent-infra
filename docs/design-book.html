第一部分：业务需求文档（BRD）

1项目背景与目标

1.1 背景

当前 AI 编程智能体（如 Claude Code CLI）能力强大但缺乏企业级管理能力：

  • 缺乏统一的任务抽象和生命周期管理
  • 缺乏资源隔离和多租户支持
  • 缺乏可观测性、审计和人工干预机制
  • 缺乏任务编排和复用能力

1.2 目标

构建一个通用的智能体任务基础设施：

  • 初期：封装 Claude Code CLI，提供编程任务的托管执行环境
  • 长期：扩展支持更多智能体类型和业务场景

1.3 设计原则

原则说明
通用性不与特定 Agent 实现强绑定，抽象层可替换
渐进式先基于 Claude Code CLI 快速落地，验证后逐步扩展
可扩展支持未来接入其他 Agent 运行时

1.4 实现策略

阶段目标
Phase 1基于 Claude Code CLI 封装，快速验证
Phase 2抽象 Agent 接口，支持多运行时
Phase 3扩展到非编程场景

2用户与角色

角色描述MVP
开发者使用 Agent 完成编码任务，创建任务、监控执行、参与审核✓
审核者对 Agent 产出进行人工审核（可与开发者合并）✓
平台管理员管理基础设施、资源配额、租户配置、模板管理✓
运维人员监控任务运行、处理异常、人工干预✓

3核心功能需求

3.1 任务定义

用户创建任务时配置：任务目标、工具集、Skills、Agents、Hooks、检查策略、资源限制。任务定义采用 YAML DSL 格式。

3.2 沙箱环境

  • 任务启动时自动创建隔离的容器环境
  • 仅激活声明的工具/Skills，未声明的进行屏蔽
  • 任务结束后环境回收

3.3 任务执行

  • 执行引擎接收任务定义，在沙箱中启动 Agent
  • 支持反馈循环：未达成目标时根据反馈调整策略重新执行
  • 执行过程实时记录，支持日志流式输出

1产品概述

1.1 产品定位

Agentic Coding Platform 是一个通用的智能体任务执行平台。底层能力通用（任务托管、沙箱隔离、执行引擎、人工干预、编排、输出管理），上层场景可扩展（编码→运维→分析→内容生成）。

1.2 核心价值

标准化

统一的任务定义格式，降低 Agent 使用门槛

可控性

资源限制、能力边界、人工干预，确保执行安全

可观测

完整的执行日志、状态追踪、审计能力

可复用

任务模板化，支持跨团队共享

可扩展

底层能力通用，支持多场景接入

1.3 产品形态

形态说明
API 服务RESTful API，供程序化调用
用户面板Web UI，面向开发者的任务操作界面
管理面板Web UI，面向管理员的运维监控界面
CLI 工具命令行工具，供开发者本地调试

1概述

1.1 设计原则

原则说明
模块化单体MVP 单体架构，模块化设计，预留微服务拆分接口
控制面与执行面分离控制逻辑与执行环境隔离，各自独立演进
异步优先核心链路采用异步处理，提升吞吐和可靠性
故障隔离单个任务失败不影响其他任务和系统稳定性
可观测优先从设计阶段内置可观测能力

1.2 架构风格

模块化单体 + 分层架构。MVP 1-2 个月快速验证，后续演进：单体 → v1.2 拆分调度服务 → v2.0 全面微服务

5.1 Task-Job 绑定

每个任务对应一个 K8s Job，Job 创建 Pod 执行任务，完成后 TTL 自动清理。选择 Job 而非 Pod/CRD：内置重试、完成追踪、自动清理。

ttlSecondsAfterFinished3600完成 1 小时后清理
restartPolicyNever不自动重启
