4.1 Auth Middleware

职责

校验请求中的 API Key，查询对应的 User 和 Tenant，注入到 Gin Context。

接口

// internal/api/middleware/auth.go

func APIKeyAuth(apiKeyRepo repository.APIKeyRepository) gin.HandlerFunc {
    // 从 Header 提取: X-API-Key 或 Authorization: Bearer xxx
    // 查询数据库: WHERE key_hash = SHA256(prefix + key)
    // 校验: 过期时间
    // 注入: ctx.Set("user_id", ...), ctx.Set("tenant_id", ...)
    // 更新: last_used_at
}

4.2 Scheduler Dispatcher

问题

现有 scheduler.Start() 只设 running = true，无后台消费循环。

设计

func (s *TaskScheduler) Start() error {
    s.running = true
    go s.dispatchLoop()  // 新增
    return nil
}

func (s *TaskScheduler) dispatchLoop() {
    ticker := time.NewTicker(1 * time.Second)
    defer ticker.Stop()
    for {
        select {
        case <-ticker.C:
            s.dispatchOnce()
        case <-s.stopCh:
            return
        }
    }
}

func (s *TaskScheduler) dispatchOnce() {
    task, err := s.Dequeue(ctx)
    if err != nil || task == nil { return }
    err = s.executor.Execute(ctx, task)
    if err != nil { s.HandleDispatchError(ctx, task, err) }
}

错误处理

错误处理
限流（并发已满）留在队列，下次重试
沙箱创建失败标记 Failed，记录错误
Context 取消优雅退出

4.3 DevOps Integration Service

职责

封装 DevOps 平台 API：需求列表、子任务管理、MR 创建、仓库信息。所有 DevOps 交互基于 DevOpsProvider 接口抽象，可替换不同平台实现。

DevOpsProvider 接口（平台抽象层）

type DevOpsProvider interface {
    // 需求级操作
    ListRequirements(ctx context.Context, opts ListOptions) ([]Requirement, error)
    GetRequirement(ctx context.Context, id string) (*Requirement, error)

    // 子任务级操作
    ListSubtasks(ctx context.Context, requirementID string) ([]Subtask, error)
    GetSubtask(ctx context.Context, id string) (*Subtask, error)

    // 仓库信息
    GetRepoInfo(ctx context.Context, repoURL string) (*RepoInfo, error)

    // MR 操作（控制面调用）
    CreateMergeRequest(ctx context.Context, req CreateMRRequest) (*MergeRequest, error)
}
// 一阶段: JDXingyunProvider（京东行云）
// 新增平台只需实现此接口

数据层级

DevOps 数据采用两级结构：需求（Requirement） 包含 子任务（Subtask），平台 Task 对应子任务级别。

type Requirement struct {
    ID          string
    Title       string
    Description string   // 含验收标准
    Priority    string   // P1/P2/P3
    RepoURL     string   // 仓库地址（子任务继承）
    Type        string   // requirement/bug/improvement
    Stage       string   // brd/prd/trd/dev/test/deploy
    ExternalURL string
    Artifacts   []Artifact
    Subtasks    []Subtask
}

type Subtask struct {
    ID          string
    Title       string
    Description string
    Type        string   // frontend/backend/testing/docs/other
    Assignee    string
    Status      string
}

type CreateMRRequest struct {
    RepoURL, SourceBranch, TargetBranch, Title, Description string
}

Service 层封装

type DevOpsService struct {
    provider DevOpsProvider
    credMgr  *CredentialManager
}

func (s *DevOpsService) ListRequirements(ctx, userID) ([]Requirement, error)
func (s *DevOpsService) GetRequirement(ctx, userID, id) (*Requirement, error)
func (s *DevOpsService) ListSubtasks(ctx, userID, reqID) ([]Subtask, error)
func (s *DevOpsService) GetSubtask(ctx, userID, id) (*Subtask, error)
func (s *DevOpsService) CreateMR(ctx, userID, req) (*MergeRequest, error)
func (s *DevOpsService) GetRepoInfo(ctx, userID, url) (*RepoInfo, error)

4.4 Credential Manager

职责

用户凭证（Git token、DevOps token）加密存储 + 沙箱注入。

接口

type CredentialManager struct {
    repo      repository.CredentialRepository
    encryptor Encryptor  // AES-256-GCM
}

func (m *CredentialManager) Store(ctx, userID, credType, value) error
func (m *CredentialManager) Get(ctx, userID, credType) (string, error)
func (m *CredentialManager) Delete(ctx, userID, credType) error
func (m *CredentialManager) BuildSandboxEnv(ctx, userID) (map[string]string, error)

数据模型

type Credential struct {
    ID        string    `gorm:"primaryKey"`
    UserID    string    `gorm:"index;not null"`
    Type      string    `gorm:"not null"`           // git_token, devops_token
    Encrypted string    `gorm:"type:text;not null"` // AES-256-GCM
    CreatedAt time.Time; UpdatedAt time.Time
    DeletedAt gorm.DeletedAt `gorm:"index"`
}
// 加密: base64(nonce + ciphertext + tag)
// 密钥: 配置文件 ENCRYPTION_KEY（32字节）

沙箱注入

Executor 创建沙箱时调用 BuildSandboxEnv()，将 GIT_TOKEN 和 DEVOPS_TOKEN 注入环境变量。

6.1 Template Preset + Task Resolution

预置模板（Seed 数据）

模板 ID名称成功标准
coding-task编码任务lint 通过 + 测试通过率 > 80%
bug-fixBug 修复lint 通过 + 测试通过 + 复现场景验证

Task Resolution 流程

1. 加载 Template spec（YAML 解析）
2. DevOps 子任务 + 需求内容填充:
   - spec.goal = subtask.Title
   - spec.description = subtask.Description（含验收标准）
   - spec.repo_url = requirement.RepoURL（从父级需求继承）
   - spec.priority = requirement.Priority
3. 用户覆盖（name, description, repo_url, branch, timeout, success_criteria）
4. 渲染 → resolved_config (JSON)

Template Spec YAML 结构

metadata:
  name: coding-task
  description: 通用编码任务模板
  scene_type: coding
spec:
  goal: ""
  description: ""
  success_criteria: [lint_pass, "test_rate > 80%"]
execution:
  tools: ["all"]
  max_timeout: 30
  max_token_budget: 0
  max_retries: 5
outputs:
  create_mr: true
  branch_prefix: "task"

10 · 安全设计

维度方案
用户认证API Key（SHA256 hash 存储），一阶段所有用户平等
内部通信X-Internal-Token 共享密钥（已有）
WebSocketws://?token=api_key，按 user scope 推送
凭证存储AES-256-GCM 加密，密钥来自配置文件
凭证注入环境变量注入沙箱，不落盘
